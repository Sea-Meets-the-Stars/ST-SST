#### Report

##### What `ExtractFields.m` does

The script is a one-off extraction driver that carves a regional
sub-cube (the Gulf of Mexico) out of the global **LLC4320b** MITgcm
output and writes it back out as plain binary tiles. It runs on NASA
Pleiades (`/nobackup*` paths) and leans heavily on a set of MATLAB
helper functions found in `kzhang/llc_4320/extract/matlab_v0`
(`quikread_llc`, `read_llc_fkij`, `llc_shrunk_read`, `readbin`,
`writebin`, `pcolorcen`, `mmax`). It proceeds in five stages:

1. **Initialize (lines 5-32).** Loads an `offsets` file (provides
   `gridDir`, `maskDir`, `FS`, `NZ`, and the `off_C/off_S/off_W`
   offset tables). Scans the input directory `dbwhitt/llc_4320/OUT`
   for `U*.shrunk` files, parses a timestamp out of each folder name
   by fixed character positions (`pnm(35:38)` = year, etc.), builds a
   `datenum` time vector, and discards everything before
   `2023-03-27`.

2. **Define region (lines 34-42).** Hard-codes the Gulf of Mexico
   lat/lon box (18.1–30.74 N, -97.91–-80.58 E) and the output root
   `kzhang/llc_4320/regions/GulfMexico/`. Precision is `real*4`.

3. **Resolve region indices (lines 44-59).** `quikread_llc` reads
   `Depth.data` and returns the field plus the **face** `fc` and the
   index ranges `ix`, `jx` that bound the lat/lon box on that face.
   The number of vertical levels `kx` is set from the deepest wet
   point (via `RF.data` → depths `bot`). Two filename suffixes are
   built: `suf1 = _NXxNY` (2D) and `suf2 = _NXxNYxNZ` (3D).

4. **Grid geometry (lines 61-148).** Reads and re-saves the static
   grid for the cut-out: cell-center fields (`RAC, XC, YC, Depth,
   hFacC`), the rotation angles (`AngleCS, AngleSN`), corner /
   vorticity points (`XG, YG, RAZ`), and the various spacing fields
   (`DXC/DYC, DXV/DYU, DXG/DYG`). The C-grid staggering shows up as
   `jx-1` index shifts on corner/edge reads.

5. **Model output (lines 150-292).** Loops over time and writes:
   - 2D scalars: `KPPhbl, Eta, PhiBot, oceQnet, oceQsw, oceFWflx`.
   - 2D vectors: wind/momentum stress `oceTAUX/oceTAUY`.
   - 3D scalars: `Salt, Theta, W` via `llc_shrunk_read` + bitmask.
   - 3D vectors: `U, V` via `llc_shrunk_read` + bitmask.
   It also emits an `extract.sh` of `extract4320` C-tool commands as
   an alternative path to pulling the 3D fields out of the
   compressed store.

##### Two ideas that are essential to porting

- **The LLC ("Lat-Lon-Cap") face geometry.** The global grid is 13
  square faces of side `FS` (4320 here). The Gulf falls on a single
  face `fc`. For faces 4 and 5 the tiles are *rotated 90°* relative to
  faces 1/2, which is why the script repeatedly swaps and sign-flips
  components: zonal velocity is `U` on faces 1/2 but `V` on faces
  4/5, meridional is `V` on 1/2 but `-U` on 4/5; the same swap is
  applied to `AngleCS/SN` and the stresses. Any Python port must
  reproduce this face-aware rotation exactly.

- **The "shrunk"/compressed storage format.** These are **not**
  standard MITgcm `mds` `.data/.meta` files. Wet points only are
  stored (land removed) and reconstructed using a **bitmask**
  (`hFacC.bits`, `hFacS.bits`, `hFacW.bits`) plus an **offsets index**
  (`offsets.idx` / `off_C/off_S/off_W`). `llc_shrunk_read` and the C
  tool `extract4320` both consume mask+offsets to inflate a requested
  `xRange/yRange/zRange` sub-box. This custom format is the single
  biggest unknown for the port — `xmitgcm`/`llcreader` read the
  standard and cloud (zarr) LLC4320, but I have not confirmed they
  read this shrunk variant.

##### How I would port it to Python

Proposed module layout under `stsst/io/` (matching the package's
flat, single-purpose style):

- `llc_grid.py` — face geometry: lat/lon box → `(face, ix, jx)`,
  vertical-level selection, and the face 4/5 rotation/sign rules in
  one well-tested place.
- `llc_binary.py` — low-level readers/writers: big-endian `real*4`
  `readbin`/`writebin` equivalents (trivial with `numpy.fromfile`/
  `tofile` + `>f4`), and a `shrunk_read` that inflates wet-point data
  with a bitmask + offsets.
- `extract_fields.py` — the orchestration layer mirroring the
  MATLAB driver: time discovery, region definition, grid save, and
  the per-field/per-time loops. Config (region box, dates, paths,
  field lists) lifted into a small dataclass or YAML, following the
  pattern already used in the sibling repo
  `llc4320-native-grid-preprocessing` (`configs/*.yaml`).
- Output: I'd recommend writing **xarray / NetCDF (h5netcdf) or
  zarr** with proper coords instead of raw `writebin` tiles — it fits
  the rest of this package's dependency stack and is far friendlier
  for the downstream Scattering Transform. We can keep a raw-binary
  writer too for parity if needed.

**Reuse / leverage:**
- `numpy`, `xarray`, `dask` cover the heavy lifting; `dask` is a
  natural fit for the time loop and the 3D cubes.
- The sibling repo `llc4320-native-grid-preprocessing` already has
  LLC face↔lat/lon and tiling helpers
  (`src/dbof/utils/faces_to_latlon.py`,
  `src/dbof/tiles/tile_mapping.py`, `preprocessing/vertical_helpers.py`)
  and `fronts/fronts/scripts/slurp_llc.py` — worth reading for
  conventions, though they target the *standard* LLC4320, not the
  shrunk LLC4320b.
- `xmitgcm` (with `llcreader`) is the obvious candidate **iff** it
  can read the shrunk files; otherwise we implement `shrunk_read`
  from the mask/offset spec.

**Suggested incremental plan** (each a future task/prompt):
1. Implement + unit-test `readbin`/`writebin` (round-trip on a small
   array).
2. Implement the LLC face/region index resolver and rotation rules.
3. Implement `shrunk_read` once the mask/offsets format is confirmed
   (this is the gating item — see Q&A).
4. Reproduce the grid-geometry extraction and validate against a
   reference cut-out from the MATLAB run.
5. Add the time-loop field extraction (start with `Theta`, since SST
   is the primary need for this package).
